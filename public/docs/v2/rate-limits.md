В API v2 действуют лимиты запросов: они обеспечивают стабильность системы, защищают от злоупотреблений и позволяют справедливо распределять ресурсы между клиентами. Лимиты определяют, сколько запросов может выполнить один пользователь за отведённый промежуток времени.

Для части методов одновременно действуют краткосрочные (в секунду) и более длительные (в минуту) ограничения. Это сдерживает всплески нагрузки, не мешая обычной работе.

## Лимиты по методам

Метод | Лимиты запросов
-------- | -----------
[Сообщения диалога](/v2/messages/get-conversation-messages) | Не более 20 запросов в минуту
[Сообщение диалога](/v2/messages/get-conversation-message) | Не более 20 запросов в минуту
[Диалоги компании](/v2/conversations/get-conversations) | Не более 10 запросов в минуту
[Получить диалог](/v2/conversations/get-conversation) | Не более 10 запросов в минуту
[Отправить сообщение в существующий диалог](/v2/messages/send-message) | Не более 5 запросов в секунду<br>Не более 30 запросов в минуту
[Написать первое сообщение](/v2/conversations/write-first-message) | Не более 5 запросов в секунду<br>Не более 30 запросов в минуту
[Получить WABA-шаблоны](/v2/waba-templates/get-waba-templates) | Не более 20 запросов в минуту

## Что происходит при превышении лимита

Если лимит превышен, API возвращает HTTP `429 Too Many Requests`. Подождите время, указанное в поле `detail` ошибки, и повторите запрос.

### Пример

```json
{
  "errors": [
    {
      "status": 429,
      "code": "too_many_requests",
      "title": "Too many requests error",
      "detail": "Please wait for 50 seconds"
    }
  ]
}
```
